================================================================================
FORESYTE BACKEND API SPECIFICATION
================================================================================

This document provides a comprehensive specification for implementing the 
ForeSyte backend API. Use this as a guide to build all required endpoints.

BASE URL: http://127.0.0.1:8000
API VERSION: v1
AUTHENTICATION: JWT Bearer Token (stored in sessionStorage as "token")

================================================================================
AUTHENTICATION & AUTHORIZATION
================================================================================

1. USER REGISTRATION (SIGNUP)
   POST /auth/signup
   Body:
   {
     "name": "string",
     "email": "string",
     "password": "string",
     "role": "student" | "admin" | "investigator" | "invigilator"
   }
   Response:
   {
     "access_token": "string",
     "user_type": "string",
     "id": "string",
     "email": "string",
     "name": "string"
   }

2. USER LOGIN
   POST /auth/login
   Body:
   {
     "email": "string",
     "password": "string"
   }
   Response:
   {
     "access_token": "string",
     "user_type": "student" | "admin" | "investigator" | "invigilator",
     "id": "string",
     "email": "string",
     "name": "string"
   }

3. GOOGLE OAUTH LOGIN
   GET /auth/google
   Redirects to Google OAuth, then redirects back to /login-success with tokens

4. ROLE SELECTION (After Google OAuth)
   POST /auth/register-role
   Body:
   {
     "email": "string",
     "name": "string",
     "role": "admin" | "invigilator" | "investigator"
   }
   Response:
   {
     "access_token": "string",
     "user_type": "string",
     "id": "string"
   }

5. TOKEN REFRESH
   POST /auth/refresh
   Headers: Authorization: Bearer {refresh_token}
   Response:
   {
     "access_token": "string"
   }

6. LOGOUT
   POST /auth/logout
   Headers: Authorization: Bearer {token}
   Response: { "message": "Logged out successfully" }

USER MANAGEMENT
================================================================================

7. GET CURRENT USER PROFILE
   GET /users/me
   Headers: Authorization: Bearer {token}
   Response:
   {
     "id": "string",
     "name": "string",
     "email": "string",
     "user_type": "string",
     "created_at": "datetime",
     "last_login": "datetime"
   }

8. UPDATE USER PROFILE
   PUT /users/me
   Headers: Authorization: Bearer {token}
   Body:
   {
     "name": "string" (optional),
     "email": "string" (optional)
   }
   Response: Updated user object

9. GET ALL USERS (Admin only)
   GET /users
   Headers: Authorization: Bearer {token}
   Query Params: ?role=student&page=1&limit=20
   Response:
   {
     "users": [...],
     "total": number,
     "page": number,
     "limit": number
   }

10. GET USER BY ID
    GET /users/{user_id}
    Headers: Authorization: Bearer {token}
    Response: User object

11. UPDATE USER (Admin only)
    PUT /users/{user_id}
    Headers: Authorization: Bearer {token}
    Body:
    {
      "name": "string" (optional),
      "email": "string" (optional),
      "user_type": "string" (optional),
      "status": "active" | "suspended" | "inactive" (optional)
    }
    Response: Updated user object

12. DELETE USER (Admin only)
    DELETE /users/{user_id}
    Headers: Authorization: Bearer {token}
    Response: { "message": "User deleted successfully" }

================================================================================
ERROR RESPONSES
================================================================================

All endpoints should return appropriate HTTP status codes:
- 200: Success
- 201: Created
- 400: Bad Request (validation errors)
- 401: Unauthorized (invalid/missing token)
- 403: Forbidden (insufficient permissions)
- 404: Not Found
- 500: Internal Server Error

Error Response Format:
{
  "detail": "Error message",
  "code": "ERROR_CODE" (optional),
  "field": "field_name" (optional, for validation errors)
}

================================================================================
DATABASE SCHEMA SUGGESTIONS
================================================================================

Tables needed:
1. users (id, name, email, password_hash, user_type, status, created_at, last_login)
2. seating_plans (id, filename, uploaded_by, uploaded_at, status, total_seats, data_json)
3. exams (id, name, course_code, instructor_id, scheduled_date, duration_minutes, seating_plan_id, status)
4. incidents (id, camera_id, student_id, exam_id, type, severity, timestamp, status, confidence, video_url, description)
5. student_documents (id, student_id, filename, uploaded_at, status, verified_by)
6. notifications (id, user_id, type, title, message, read, created_at)
7. exam_assignments (exam_id, student_id, room_id, seat_number)

IMPLEMENTATION NOTES

2. Implement role-based access control (RBAC) for endpoints
3. Use PostgreSQL or MySQL for database
4. Implement file upload handling for PDFs and documents
5. Use async/await for database operations
6. Implement proper error handling and logging
7. Add rate limiting for API endpoints
8. Use environment variables for sensitive configuration
9. Implement database migrations for schema management
10. Add input validation for all endpoints
11. Use proper HTTP status codes
12. Implement pagination for list endpoints
13. Add filtering and sorting capabilities
14. Use proper CORS configuration for frontend integration
